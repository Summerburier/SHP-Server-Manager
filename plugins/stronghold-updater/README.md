# 卫戍协议 · 定时更新（stronghold-updater）

每天定时更新 **Stronghold-Protocol（卫戍协议：盟约）**，默认 04:00。支持**回滚**与**超时设置**。

## 绑定服务（不再手填路径）

插件从**实例绑定的服务**读取目标目录：`context.service` → 该服务的 `path`。
- **项目服务**：`path` 就是服务配置里的本地项目目录 `project.path`。
- **systemd 服务**：后台会通过 `systemctl show <unit> --property=WorkingDirectory` 取到该单元的工作目录作为 `path`；更新完成后插件执行 `systemctl restart <unit>`（配置了 `sudo` 时用 `sudo -n systemctl`）使其生效。

所以：

1. 先在“服务”里配好这个 Stronghold-Protocol（`source` 指向它的目录，或作为项目服务）。
2. 在插件实例上绑定该服务即可，插件自动使用它的目录，无需再填写路径。

未绑定服务、或服务没有本地目录（仅 URL / systemd 无目录）时，实例会显示“未就绪”并在卡片内提示原因。

## 三个设置

| 设置 | 说明 |
| --- | --- |
| `更新方式` | `官方增量更新包`（默认）或 `Git 拉取` |
| `每天几点更新` | 0–23，默认 4 |
| `下载 / 拉取超时（分钟）` | 1–180，默认 30（受带宽影响，可按需调大） |

点击插件卡片进入可管理多个实例：实例列表可滚动，列表底部有一张空白卡片用于添加实例。

## 操作按钮（实例上）

- **立即更新**：不等计划，马上跑一次。

## 回滚（全自动，无需人工）

- **官方增量更新包**：应用前把本次会覆盖 / 删除的文件备份到后台数据目录（`data/stronghold-updater/<实例>/backups/`，**不写入 Stronghold-Protocol 目录**），并记录会新增的文件；一旦官方校验失败（更新包与当前安装不匹配等），**自动回滚**：恢复文件、删除新增文件、清理 `UPDATE.json` 与空目录，并在实例上以警告提示。
  - 只保留最近一个回滚点。
- **Git 拉取**：`git pull --ff-only` 失败不会改动工作区，无需回滚。

## 注意

- 更新后需**重启游戏服务**才生效：systemd 绑定的服务由插件自动 `systemctl restart`；项目服务由本后台托管，请在“服务”页点重启。
- 解压需要系统自带 `tar`（Win10+/macOS）或 `unzip`（Linux）。
- 状态与回滚点都保存在后台数据目录 `data/stronghold-updater/<实例>/`，**不会往 Stronghold-Protocol 目录里写任何插件文件**（只按官方更新机制覆盖官方文件本身）。
- 该插件更新的是 **Stronghold-Protocol 本体**，与管理后台无关。
